# PostgreSQL API для Mounter

Android звертається до API, а API — до PostgreSQL. Пароль БД зберігається лише на комп’ютері сервера.

## Підключення до наявного Flask-сервера

Для сервера `http://192.168.1.76:5001` додайте `directory_api.py` і `config.py` у його Python-каталог, встановіть залежності та зареєструйте Blueprint:

```python
from directory_api import directory_api
app.register_blueprint(directory_api)
```

Маршрути мають окремий префікс `/api/mounter` і не змінюють існуючі маршрути. Якщо у сервері вже є `config.py`, перенесіть DB_CONFIG та налаштування ідентифікаторів у його конфігурацію або змініть імпорт у `directory_api.py`. Використовуйте правила автентифікації наявного сервера при підключенні цього Blueprint.

## Окремий запуск на комп’ютері з PostgreSQL

Команди нижче виконуються в каталозі `server`:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env
# Windows PowerShell: Copy-Item .env.example .env
python main.py
```

Окремий `main.py` запускайте лише якщо порт 5001 не зайнятий вашим сервером. Для наявного сервера використайте підключення Blueprint вище.

У `.env` уже наведені параметри тестової БД із завдання. `DB_HOST=localhost` означає комп’ютер, на якому запущено API. Файл `.env` не додається до Git.

Очікувані стовпці:

- `public.employees`: `id` (унікальний), `full_name`, `job_title`, `image_url`.
- `public.clients`: `id` (унікальний), `name`.

Якщо ідентифікатори називаються інакше, задайте `EMPLOYEE_ID_COLUMN` і `CLIENT_ID_COLUMN` у `.env`. Таблиці не створюються і не змінюються. Запити лише читають довідники; SQL-параметри передаються окремо від тексту запиту.

## Адреса в застосунку

Натисніть індикатор БД на головній і задайте адресу API. Початкова адреса — `http://192.168.1.76:5001`; при зміні динамічного IP можна вказати нову:

- Android Emulator: `http://10.0.2.2:5001`.
- Фізичний планшет: `http://192.168.1.76:5001`.
- Для сервера з HTTPS: `https://<домен>`.

Планшет має мати доступ до порту 5001 сервера. PostgreSQL на порту 5432 доступний API; Android безпосередньо до нього не підключається. Для локального тестового API дозволено HTTP.

`image_url` може бути абсолютною HTTP(S)-адресою або шляхом відносно API. Зображення має бути доступне планшету за цією адресою; цей API не обслуговує локальні файли PostgreSQL. Відносні шляхи потребують відповідного файлового маршруту на сервері зображень.

## Маршрути

- `GET /api/mounter/health`: перевірка справжнього підключення запитом `SELECT 1`.
- `GET /api/mounter/employees?q=<ПІБ>`: до 30 збігів за `full_name`, регістр не враховується; порожній пошук не повертає весь довідник.
- `GET /api/mounter/employees/selected?ids=<id>&ids=<id>`: оновлення збережених співробітників за їхніми ідентифікаторами.
- `GET /api/mounter/clients?q=<назва>`: до 30 замовників за `name`, включно з початковими пропозиціями при порожньому запиті.

При помилці підключення або схеми API повертає 503 із повідомленням, яке застосунок показує у спливаючому повідомленні. Деталі пароля не передаються в Android. Перевірка підключення повторюється кожні 30 секунд, доки застосунок активний.

Склад бригади зберігається локально за реальними ID, із кешем ПІБ та фото. Старі демонстраційні індекси співробітників не прирівнюються до ID PostgreSQL. Об’єкти, блоки, фото та примітки наразі зберігаються локально; замовник обирається із БД і його ID записується разом з об’єктом.

Адреса й схема задані за даними користувача. За його вказівкою компіляцію, тести та запити до реального сервера не запускали.
