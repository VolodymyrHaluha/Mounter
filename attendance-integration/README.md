# Сукупний доступ Mounter за кількома NFC-картками

Поточне правило: доступ дозволено, доки хоча б одна картка має підтверджений
LOCAL `check_in`, незавершену сесію і не має нового непідтвердженого виходу.
Попереднє правило відкриття за локально збереженою відміткою без LOCAL більше
не застосовується. Старий provider без колонки `sessions` не відкриває Mounter.

## Mounter

Єдиний AttendanceGate охоплює головну сторінку, об’єкти, бригаду, деталі об’єктів
і їхні діалоги. Після виходу останньої картки весь MounterApp вилучається з
композиції. Повторні перевірки не закривають чинний доступ. Нове сканування,
скасування фотографування й помилка запуску APP-TEST не скидають підтверджений стан.
Зміна вибраного додатка відміток потребує нової перевірки його provider.

На головній сторінці показано сесії кожної картки, незалежні години та кількість
активних карток. Завершені сесії зберігаються; їхні години можна побачити також
на екрані відмітки після блокування.

## APP-TEST

У цьому репозиторії є шаблони інтеграції, але немає повного проєкту APP-TEST.
Зміни набудуть чинності лише після внесення їх в APP-TEST та встановлення обох
оновлених додатків.

Для попередньої **серверної** інтеграції з MounterAttendanceContent застосуйте:

```sh
python attendance-integration/update_attendance_bridge.py /path/to/APP-TEST
```

Скрипт перевіряє наявність потрібних точок інтеграції, створює резервні копії,
оновлює bridge, LOCAL-підтвердження і передає `pending.identification` у
`recordSaved(context, record, pending.identification)`. Спільну чисту модель
`CardSessions.kt` копіює з Mounter; пакет моделі залишається
`com.example.mounter.attendance`. Для первинної серверної інтеграції використайте
`integrate_attendance.py`. Для старої версії PR #15 — `upgrade_attendance_return.py`.

**Не застосовуйте ці скрипти поверх гілки offline-attendance.** Для неї потрібно
адаптувати точки збереження і відповіді LOCAL до нової моделі. Вхід без LOCAL
не відповідає цій вимозі. Повний вихідний код цієї гілки тут відсутній.

Bridge зберігає повний незмінний список сесій одним `SharedPreferences.commit()`
під спільним блокуванням із читанням provider. `notifyChange` викликається після
успішного збереження. Не існує проміжного скидання всіх карток у `locked`.
Збереження нової відмітки призупиняє право лише відповідної картки; LOCAL
визначає остаточну дію. Початок або скасування фотографування стан не змінює.
Підтвердження приймається тільки для актуального pending UUID цієї картки.
Повторні збереження того самого UUID і застарілі відповіді не перемикають стан.
GLOBAL не підтверджує доступ. Опитування LOCAL охоплює pending-події всіх карток.

Часи в шаблоні bridge фіксуються при збереженні відмітки на пристрої;
підтвердження LOCAL не пересуває початок або кінець таймера. Якщо модель APP-TEST
містить первинний час NFC-події, передавайте саме його замість поточного часу
в `saveCardEvent`. Мітки карток походять із `pending.identification`.

Попередній одиночний стан доступу не конвертується в підтверджену багатокарткову
сесію без відомої картки. Після оновлення потрібен новий підтверджений прихід.
Історія в основній БД APP-TEST не видаляється.

## Перевірка

`CardSessionsTest` перевіряє сукупний доступ, проміжні стани при виході А за
активної Б, непідтверджені дії, застарілі відповіді, дублікати UUID, незалежні
таймери та збереження завершених сесій. Перевірки на пристрої мають додатково
охопити ContentProvider, перезапуски обох процесів, скасування фото та блокування
з кожного розділу. Повна стандартна збірка потребує Android SDK 37.1.
