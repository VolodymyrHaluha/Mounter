# Відмітки перед відкриттям Mounter

Інтеграція складається з Mounter, оновленого додатка відміток (`com.example.app`)
та LOCAL-сервера. Потрібно встановити версії обох додатків із наведеними змінами.
Mounter не звертається до БД або HTTP API; усі серверні запити виконує додаток відміток.

## Додаток відміток

Якщо вже застосували інтеграцію з PR #15, оновіть її цим скриптом:

```sh
python attendance-integration/upgrade_attendance_return.py "шлях/до/проєкту/відміток"
```

Він зберігає попередні файли як `*.before-mounter-return-v2`, додає кнопку
«Повернутись до монтажників» і механізм автоматичного повернення через callback.
Після застосування зберіть та встановіть оновлений додаток відміток і Mounter.
Не застосовуйте первинний скрипт повторно до вже інтегрованого проєкту.

Якщо інтеграцію ще не застосовували, використайте первинний скрипт нижче.

Виконайте з репозиторію Mounter, вказавши папку проєкту додатка відміток:

```sh
python attendance-integration/integrate_attendance.py "шлях/до/проєкту/відміток"
```

Скрипт також приймає папку, у якій лежить розпакована `src`. Зміни додають два
Kotlin-файли, provider у manifest, обробку NFC-мітки, переданої Mounter,
та перевірку серверного підтвердження. Копії змінених файлів мають суфікс
`.before-mounter`. У Kiosk Mode список дозволених додатків включатиме Mounter.
Повторний запуск не перезаписує наявні зміни або резервні копії.

Після цього зберіть і встановіть додаток відміток у своєму Android Studio.
Ця інтеграція не змінює його налаштування серверів, облікові дані чи бібліотеки.

## LOCAL-сервер

Виконайте для наданого LOCAL `app.py`:

```sh
python attendance-integration/integrate_local_server.py "шлях/до/LOCAL/app.py"
```

Скрипт створює `app.py.before-mounter`, додає модуль `server_mounter_state.py`
і виправляє відповідь POST після перерахунку історії працівника. Перезапустіть LOCAL.
Схема БД, адреса сервера та налаштування доступу залишаються на вашому сервері.

Новий маршрут `GET /api/attendance/events/<external_uuid>/mounter-state`
перевіряє зареєстрований пристрій, належність відмітки цьому пристрою, активність
працівника та NFC-ідентифікатора. Він повертає `ok`, `external_uuid`, `employee_id`,
`identity_type`, `server_action`, `sync_status`. Доступ до маршруту має проходити
через ті самі мережеві/автентифікаційні правила, що й чинний LOCAL API.

## Поведінка

- Перед меню Mounter є екран із кнопкою відкриття додатка відміток.
  Вона доступна під час перевірки зв’язку; запуск визначає фактичну launcher-activity,
  Якщо Android не знаходить launcher-activity, Mounter явно запускає
  `com.example.app.MainActivity`, яка експортується в наданому manifest APP-TEST.
  Помилка запуску показується на цьому екрані; відсутність activity та заборона
  Android мають окремі повідомлення. Обидва додатки мають бути встановлені
  в одному профілі Android.
- Mounter передає NFC-мітку додатку відміток, який виконує наявне фотографування
  та збереження. Нове зчитування одразу закриває доступ до меню.
- `check_in` від LOCAL для тієї самої NFC-відмітки відкриває меню;
  `check_out` блокує його до нового підтвердженого `check_in`.
- Поточний підтверджений стан «Прихід» відкриває меню після повернення в Mounter
  або натискання «Перевірити відмітку». Додаткового збігу ідентифікатора запуску
  чи номера NFC-зчитування для доступу не потрібно.
- Після обох підтверджених дій додаток відміток автоматично повертає користувача
  в Mounter. Для ручного повернення доступні кнопка «Повернутись до монтажників»
  та системна дія «Назад». Саме повернення не надає доступу до меню.
- Повернення використовує одноразовий immutable PendingIntent, створений Mounter.
  Ідентифікатор запиту використовується для повернення з додатка відміток.
  Повторний запуск існуючої activity також обробляється.
- Наявний POST на LOCAL може одразу підтвердити дію через `server_action`,
  `external_uuid`, `employee_id`, `identity_type` та `sync_status`.
  GET-перевірка залишається для повторних відправок і імпорту GLOBAL.
- HTTP 200, `ok: true`, успішне фото, запис помилки синхронізації чи підтвердження
  GLOBAL без остаточного запису на LOCAL не відкривають меню.
- Якщо відмітка потрапила на GLOBAL, додаток чекає її імпорту на LOCAL;
  коли LOCAL доступний, її стан перевіряється кожні п’ять секунд.
- Помилка мережі не скасовує вже підтверджений прихід до нового NFC-зчитування.
  Під час нової відмітки або після скасування її фотографування стан очікування
  залишає меню закритим. Якщо лише відкрити й закрити додаток відміток без нового
  зчитування, чинний підтверджений «Прихід» зберігає доступ.
- NFC-повтори протягом десяти секунд ігноруються, щоб утримання картки біля
  антени не створило наступну відмітку одразу після приходу.
- Дані об’єктів і бригади залишаються на пристрої. Відмітка не очищає їх.

До встановлення оновленого додатка відміток Mounter показує повідомлення про
відсутність зв’язку й не відкриває меню. Немає ручної кнопки обходу перевірки.
Provider дозволяє читати лише стан доступу додатку `com.example.mounter`;
ідентифікатор NFC та фото через нього не передаються, запис ззовні заборонений.

Перевірки на пристрої: прихід, повторна NFC-відмітка/вихід, наступний прихід,
скасоване фото, відсутність мережі, відмітка через GLOBAL з подальшим імпортом,
повторна відправка UUID після втрати відповіді та Kiosk Mode.
Компіляцію й тести під час підготовки змін не запускали.
